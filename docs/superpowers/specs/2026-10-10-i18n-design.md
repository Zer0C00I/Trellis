# Переводы (i18n) киоска и приложения для родственников — Design Spec

Дата: 2026-10-10
Статус: утверждён в обсуждении, ждёт ревью спеки
Затрагивает: `kiosk-gui`, `family-app/src-tauri`, `family-app/ui`
Не затрагивает: `web/` (сайт уже английский), программу `family-vault`, `tools/*`

## Цель

Киоск и приложение для родственников показывают текст на русском или английском. Сегодня текст зашит по-русски в трёх местах: `.slint` киоска, Rust-строки киоска и приложения, JS приложения. Побочная цель: чинится раскладка киоска, где длинные русские подписи не помещаются в кнопки, а кнопка помощи `?` перекрывает список получателей.

Языки: русский (`ru`) и английский (`en`). Третий язык позже добавляется без изменений кода (папка `.po` для киоска, один JSON для приложения).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Охват | Киоск и приложение. Сайт не меняется. |
| Язык киоска | Задаётся при настройке: поле `language` в `kiosk.toml`; нет поля, берётся `LANG`; нет и его, русский. Переключателя на экране нет. |
| Язык приложения | Сохранённый выбор, иначе язык системы (`ru`/`en`), иначе английский. Переключатель на вкладке «Я», перерисовка сразу. |
| Киоск: механизм | Встроенные переводы Slint: `@tr()` в `.slint`, файлы `.po`, встроенные в бинарник. Rust не пишет фраз, он выставляет состояние и параметры. |
| Приложение: механизм | Rust не знает языков и возвращает ключи с параметрами. Один JSON-каталог на язык в `family-app/ui/locales/`. Множественные числа, даты, числа: `Intl`. |
| Деньги | Суммы остаются строками от Rust ("250.5 USDC"), как сейчас. Разделитель не локализуется. |

## 1. Киоск

### 1.1 Как работают переводы Slint (проверено в исходниках slint 1.18.0)

- `slint_build::CompilerConfiguration::with_bundled_translations(путь)` встраивает переводы при сборке. Файлы лежат как `<путь>/<язык>/LC_MESSAGES/<крейт>.po`, то есть `kiosk-gui/translations/ru/LC_MESSAGES/kiosk-gui.po`.
- После создания первого окна вызывается `slint::select_bundled_translation("ru")`. Пустая строка или `"en"` выбирает исходный язык: сам текст внутри `@tr("…")`.
- Системный gettext не нужен (фича `gettext` для встроенных переводов не требуется).
- Следствие: **исходные тексты в `.slint` становятся английскими**, русский переезжает в `.po`. Для русского множественного числа в заголовок `.po` пишется `Plural-Forms` с тремя формами.

### 1.2 Выбор языка

Чистая функция `resolve_language(из_конфига: Option<&str>, lang_env: Option<&str>) -> Language` (в `kiosk-gui/src/language.rs`):
1. значение из конфига, если это `ru` или `en` (без учёта регистра);
2. иначе префикс `LANG` (`ru_RU.UTF-8` даёт `ru`, `en_US.UTF-8` даёт `en`);
3. иначе `ru`.

Неизвестное значение в конфиге не ошибка: пишется строка в `stderr`, и язык определяется дальше по цепочке.

Где язык лежит:
- `kiosk.toml`: необязательное поле `language`. `RawConfig` в `chain.rs` получает `#[serde(default)] language: Option<String>`; `ChainConfig` его не хранит, язык нужен только до создания интерфейса.
- `provisioning.toml`: то же необязательное поле. `write_kiosk_config` копирует его (или язык, определённый по `LANG` в момент настройки) в `kiosk.toml`, чтобы позже язык менялся правкой одной строки.
- Экран настройки показывается до появления `kiosk.toml`, поэтому язык берётся из `provisioning.toml` или `LANG` ещё до создания окна: порядок в `run()` такой: прочитать язык, `AppWindow::new()`, `select_bundled_translation`.

Уже настроенные устройства без поля `language` и без `LANG` остаются русскими: поведение не меняется.

### 1.3 Текст принадлежит Slint, Rust отдаёт состояние

Rust перестаёт содержать русские фразы. Вместо них:

```slint
export enum Message {
    none, no-connection, failed, contact-support, done,
    setup-waiting, setup-almost-done, setup-adding-member, setup-show-code,
}
```

и свойства окна: `balance-message`, `family-balance-message`, `result-message` (все `Message`), `result-name` (строка, имя получателя), `setup-message` (`Message`), `pairing-wait-secs` (число, `0` значит «нет ожидания»). Соответствие `Message` → текст описано один раз в `.slint` через `@tr`:

- `no-connection`: "No connection. Try again later"
- `failed`: "That did not work. Try again or call a relative"
- `contact-support`: "That did not work. Contact support"
- `done`: `@tr("Done! Money sent to {}", result-name)`
- `setup-waiting`: "Waiting for confirmation…", `setup-almost-done`: "Almost done…", `setup-adding-member`: "Adding a family member…", `setup-show-code`: "Show this code to the relative who will have access to the family app"
- Ожидание при подборе кода: `@tr("Wait {} sec, then scan this code in the family app or type the digits:", …)` и вариант с минутами; при `pairing-wait-secs == 0` показывается "Scan this code in the family app or type the digits:". Секунды/минуты: `@tr("{n} second" | "{n} seconds" % n)`.

Остальные надписи (заголовки экранов, кнопки "Send", "Cancel", "Back", "Help", "OK", "Skip", "Family wallet", "My wallet", "Back to my wallet", "Device setup", подсказки на экране суммы и подтверждения) переходят в `@tr` на месте. Имена получателей и баланс это данные, не переводятся. Метки доступности (`accessible-label`) тоже под `@tr`.

Следствия для Rust:
- `error_message_text` заменяется функцией `error_message(&ChainError) -> Message`.
- `pairing::pairing_instruction` и `display_wait` (форматирование "N сек."/"N мин.") удаляются, остаётся расчёт секунд. Тесты, которые сегодня ищут слово «Подождите» (`lib.rs`, около строк 898–902), проверяют `pairing-wait-secs > 0` и `== 0`.
- `"Получатель"` по умолчанию (`found_name`) заменяется пустым именем и `@tr("Recipient")` в Slint, когда имя пусто.

### 1.4 Раскладка

- Кнопка `?` (помощь) закрепляется в своей колонке: списки получателей получают правый и нижний отступ, равный размеру кнопки плюс интервал, так что `?` не может лежать поверх строки. Это относится к экранам «Мой кошелёк» и «Семейный кошелёк».
- Экран результата: кнопка `OK` по центру (`horizontal-stretch`/выравнивание в центр), а не прижатая к левому краю.
- Подписи на кнопках переносятся по словам (`wrap: word-wrap`), кнопка растёт по высоте от минимума 60 пикселей (`min-height`, не фиксированная `height`), а не обрезает текст. Кнопка «Family wallet» в правом верхнем углу получает достаточную ширину под английский и русский вариант.
- Автопроверка (тестовый бэкенд Slint): для каждого экрана в обоих языках ни один `Text` не выходит за границы своей кнопки или экрана; проверяется по геометрии элементов (`ElementHandle`), включая самое длинное имя получателя (32 байта).

### 1.5 Тесты и инструменты киоска

- Тест полноты `.po`: для каждого `@tr("…")` в `ui/*.slint` в `ru.po` есть запись с непустым `msgstr`; для форм с множественным числом заполнены все три формы. Простой разбор `.slint` и `.po` без внешних зависимостей, как тест в `tests/`.
- Тест `resolve_language` на все ветки цепочки.
- Тесты навигации (`tests/navigation.rs`) ищут элементы по меткам доступности и переходят на исходный английский язык (метки "Family wallet" и т.п.): они не зависят от `.po`.
- Снимки обоих языков (скрипт, как для презентации) для ручного просмотра раскладки.

## 2. Приложение для родственников

### 2.1 Каталог и модуль `i18n.js`

`family-app/ui/locales/en.json` и `ru.json`: плоские ключи вида `home.send`, значения с параметрами `{name}`. Формы множественного числа задаются объектом `{"one": "...", "few": "...", "many": "...", "other": "..."}` и выбираются `Intl.PluralRules(locale).select(n)`; в `en.json` нужны только `one` и `other`.

`i18n.js` (чистый модуль, тестируется в Node):
- `t(key, params)`: ищет в текущем языке, затем в английском; параметры подставляются по именам; неизвестный ключ возвращает сам ключ и пишет предупреждение в консоль (в тестах это ошибка).
- `setLocale(locale)`, `currentLocale()`, `detectLocale({stored, navigatorLanguage})`: сохранённый выбор, иначе префикс `navigator.language` (`ru`/`en`), иначе `en`.
- Выбор сохраняется в `localStorage` под ключом `trellis.locale` с обработкой ошибок (хранилище может быть недоступно), как остальные настройки интерфейса.
- `formatTime` (сегодня жёстко русский: «сегодня», сокращения месяцев) переходит на `Intl.DateTimeFormat(locale)` и `Intl.RelativeTimeFormat` для слова «сегодня»; его тесты обновляются.

Смена языка: вкладка «Я» получает переключатель «Язык / Language» (две кнопки RU / EN). `setLocale` + перерисовка всего экрана, без перезапуска.

### 2.2 Rust возвращает ключи

`text.rs` перестаёт строить фразы. Типы DTO меняются так:

| Сейчас | Станет |
|---|---|
| `ErrorDto { kind, message, details }` | `ErrorDto { kind, key, params, details }` |
| `ActionOkDto { signature, message }` | `ActionOkDto { signature, key, params }` |
| `PayeeDto.status: String` | `PayeeDto.status: { key, params }` (`payee.ready`, `payee.wait_hours` с `n`, `payee.wait_under_hour`) |
| `HistoryLineDto.text: String` | `HistoryLineDto { signature, key, params, time }` (`history.deposit` с `amount`, `history.recipient_added` с `name`, …) |
| `ResolutionDto.message` | `ResolutionDto { status, key }` |
| `VaultDto.title` | убирается: JS выводит заголовок из `is_pool` |
| `PendingTxDto.what: String` | `PendingTxDto { what_key, what_params, signature }` |

`params` это объект `{ amount: "5 USDC", name: "…", n: 5 }`. Суммы форматирует Rust (`money`), имена очищает `sanitize_text`; JS подставляет их как есть.

Рукописные `plural_ru` и `short_address` с текстом уходят: множественное число даёт `Intl`, а `short_address` остаётся (это не язык).

`friendly_rejection` (код ошибки программы → предложение) возвращает ключ `error.vault.<ИмяОшибки>`, неизвестный код: `error.rejected_generic`. Ключи: `error.no_connection`, `error.rejected_generic`, `error.unconfirmed`, `error.blocked.*`, `pairing.*`, `notice.*` (успехи), `resolution.*`.

**Файл неподтверждённой операции** (`pending-transaction.json`) хранит `what` как готовую фразу. Он получает поля `what_key` и `what_params`; поле `what` читается как запасное (`#[serde(default)]`), чтобы запись, созданная старой версией приложения, не терялась: если нового ключа нет, показывается общий текст "An earlier operation is unfinished" со старой фразой в `details`.

### 2.3 Интерфейс и мок

- Все русские строки в `app.js`, `components.js`, `screens/*.js`, `mock-api.js` заменяются на `t('ключ', {…})`. Мок-бэкенд возвращает те же ключи и параметры, что и Rust (форма DTO одна).
- Смоук-тест принимает `?lang=ru|en` и прогоняется в обоих языках (`tools/smoke.mjs` запускает набор дважды). Проверки текста в нём переписываются на ключевые слова через `t()` либо на структуру (классы баннеров), чтобы не дублировать фразы в тесте.
- Проверка переполнения: в каждом языке на каждом экране при ширине 360 пикселей `document.documentElement.scrollWidth <= clientWidth` и ни одна кнопка не выходит за карточку.

### 2.4 Тесты каталога (Node)

- Наборы ключей `en.json` и `ru.json` одинаковы.
- У каждого ключа одинаковый набор параметров `{…}` в обоих языках; у форм множественного числа заполнены все формы нужного языка.
- Каждый ключ, который использует код (`t('…')` в `ui/*.js`, `screens/*.js`, ключи, возвращаемые Rust: список ключей в `family-app/src-tauri` проверяется отдельным Rust-тестом против `en.json`), существует; нет лишних ключей, которые нигде не используются.
- Rust-тесты: функции, которые раньше проверяли русские предложения, проверяют ключи и параметры.

## 3. Что не входит

- Сайт `web/`: остаётся английским, без переключателя.
- Третий язык и правосторонние письменности.
- Локализация разделителя сумм ("250,5" вместо "250.5").
- Перевод сообщений программы в блокчейне и системных ошибок Solana (идут в `details`).
- Английские формулировки пишутся в этой работе; перед выпуском их должен просмотреть владелец продукта (носитель языка лучше).

## 4. Риски и решения

- **Тесты навигации киоска** зависят от меток доступности на русском. Решается переходом на английский исходный язык в тестах (метки стабильны и не зависят от `.po`).
- **Новые строки** в будущем: тест полноты `.po` и тест каталога ломают сборку, если перевод забыт.
- **Размер**: около 50 строк в киоске и около 250 в приложении. Работа независима по двум частям.
- **Совместимость файла неподтверждённой операции** описана выше (чтение запасного поля `what`).

## 5. Порядок работы

Одна спека, два плана, которые выполняются по очереди:
1. Киоск: язык, `@tr`/`.po`, перевод состояний, раскладка, тесты.
2. Приложение: `i18n.js`, каталоги, ключи вместо фраз в Rust, смоук в двух языках, переключатель на вкладке «Я».

После обоих планов английские снимки для презентации делаются штатно, без временных копий с переводом.
