# Kiosk i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The kiosk shows Russian or English, chosen once at setup, and its buttons no longer break with long Russian labels (help `?` no longer overlaps the beneficiary list, OK is centred, labels wrap and buttons grow).

**Architecture:** Slint bundled translations: the `.slint` source text becomes English `@tr("…")`, Russian lives in `kiosk-gui/translations/ru/LC_MESSAGES/kiosk-gui.po`, and the language is selected at start-up with `slint::select_bundled_translation`. Rust never sends human text to the UI any more: it sets a `Message` enum (and numbers/names) and the UI words them through a `Messages` global with pure functions. One shared `KioskButton` wraps its label and grows with it.

**Tech Stack:** Rust, Slint 1.18 (`slint-build` bundled translations, `i-slint-backend-testing`), `toml`.

**Spec:** `docs/superpowers/specs/2026-10-10-i18n-design.md`, section 1 (kiosk). The family-app half of the spec is a separate plan.

## Global Constraints

- **Languages:** `ru` and `en` only. Language chain: `language` in `kiosk.toml`, else `language` in `provisioning.toml` next to it, else `LANG`, else `ru`. No switcher on screen.
- **Source text is English.** Every static label in `.slint` is `@tr("English text")` (default translation context disabled). The Russian text exists only in the `.po`.
- **Rust sends no human text to the UI.** It sets `Message` values, numbers (`pairing-wait-secs`) and names. Names and amounts from the chain are not translated.
- **No plural forms in the kiosk.** Time units are abbreviations (`{} sec` / `{} сек.`, `{} min` / `{} мин.`).
- **Touch targets:** 60 px minimum, 16 px spacing, pure black on white (existing `Theme`). Buttons never shrink below 60 px and grow with their label.
- **Rust:** `[lints.rust] unsafe_code = "deny"`, `dead_code = "deny"`. `cargo clippy -p kiosk-gui --all-targets` clean. Do NOT run `cargo fmt -p kiosk-gui`: the package has older unformatted files and it would rewrite unrelated code. Format only files you create, with `rustfmt --edition 2021 <file>`.
- **Commits:** work directly on `master` (project convention). Do not add attribution lines to commit messages. Do not touch `Cargo.lock`: no task adds a dependency.
- **Tests that must keep passing:** `cargo test -p kiosk-gui` (the `navigation` test binary has `harness = false`; its scenarios run from one `main()`).

## How the code is delivered

Every task below ships as a patch file in `docs/superpowers/plans/kiosk-i18n/`. The patches were produced by implementing the tasks in order on a clean export of `master` at `ceec852`, and were then re-applied in order to a fresh export of `master` where the full `cargo test -p kiosk-gui` passed. Apply each with `git apply --index <patch>` from the repo root, in order, then run the task's checks. If a patch does not apply, `master` has moved: read the patch (it is a plain unified diff and is the specification of the change) and make the same change by hand.

- Patch: `docs/superpowers/plans/kiosk-i18n/2-bundled-translations.patch`

**Interfaces:**
- Consumes: `Language::code()` from Task 1.
- Produces: every static label is `@tr("English")`; the `.po` has an entry for each; after `AppWindow::new()` the app calls `slint::select_bundled_translation(language.code())`.

- [ ] **Step 1: Apply the patch**

```bash
git apply --index docs/superpowers/plans/kiosk-i18n/2-bundled-translations.patch
```

`build.rs` becomes:

```rust
let config = slint_build::CompilerConfiguration::new()
    .with_debug_info(true)
    .with_bundled_translations("translations")
    .with_default_translation_context(slint_build::DefaultTranslationContext::None);
```

(`None` keeps the `.po` free of `msgctxt`, so entries are plain `msgid`/`msgstr` pairs.) `tests/translations.rs` holds a small `@tr` extractor and `.po` reader and three checks: every `@tr` has a non-empty Russian entry, no `.po` entry is stale, placeholder counts match. `tests/navigation.rs` now finds buttons by their English labels and gains `the_russian_translation_is_bundled_and_can_be_selected`.

(b) Remove `.with_bundled_translations("translations")` from `build.rs`, run `cargo test -p kiosk-gui --test navigation`: it must fail with `NoTranslationsBundled`. Restore the file.

### Task 3: The UI words messages from state

**Files:**
- Create: `kiosk-gui/ui/messages.slint`
- Modify: `kiosk-gui/src/lib.rs`, `kiosk-gui/src/pairing.rs`, `kiosk-gui/tests/navigation.rs`, `kiosk-gui/translations/ru/LC_MESSAGES/kiosk-gui.po`, `kiosk-gui/ui/{app,amount-select,confirm,family-wallet,my-wallet,result,setup}.slint`
- Patch: `docs/superpowers/plans/kiosk-i18n/3-messages.patch`

**Interfaces:**
- Consumes: Task 2's `.po` and `select_bundled_translation`.
- Produces (Slint): `export enum Message { none, no-connection, failed, contact-support, done, setup-waiting, setup-almost-done, setup-adding-member, setup-show-code }`; `export global Messages` with pure functions `text(message, name) -> string`, `recipient(name) -> string` (empty becomes `Recipient`), `pairing-instruction(wait-secs: int) -> string`. `AppWindow` properties: `setup-message`, `pairing-wait-secs`, `balance-message`, `family-balance-message`, `result-message`, `result-name` (replacing `setup-status-text` and `result-message-text`).
- Produces (Rust): `pairing::wait_seconds(wait: Option<Duration>) -> i32` (rounded up, `0` for `None`, saturating); `error_message(&ChainError) -> Message`; `set_setup_message(&Weak<AppWindow>, Message)`.

- [ ] **Step 1: Apply the patch**

```bash
git apply --index docs/superpowers/plans/kiosk-i18n/3-messages.patch
```

What changes: no Russian literal is left in non-test Rust. `display_wait` and `pairing_instruction` (and their three tests) are removed from `pairing.rs`; the pairing sentence is built in `Messages.pairing-instruction`: below 60 s `"Wait {} sec, then scan this code in the family app or type the digits:"`, above it `"Wait {} min, …"` with `Math.ceil(wait-secs / 60)`, zero gives `"Scan this code in the family app or type the digits:"`. The stale-timer unit test now sets its sentinel (7) from a follow-up event-loop closure, because `hide_pairing_view` resets the wait to 0 in its own queued closure.

### Task 4: Buttons that grow with their label

**Files:**
- Create: `kiosk-gui/ui/button.slint`
- Modify: `kiosk-gui/ui/{theme,amount-select,confirm,family-wallet,my-wallet,result,setup}.slint`, `kiosk-gui/tests/navigation.rs`
- Patch: `docs/superpowers/plans/kiosk-i18n/4-layout.patch`

**Interfaces:**
- Produces: `export component KioskButton inherits Rectangle` with `in property <string> text`, `in property <bool> primary: true` (false: white with a 2 px border), `in property <length> font-size: Theme.font-size-body`, `callback clicked()`; `min-height: Theme.target-size`; the label is a wrapping `Text` with `min-width: 0px` (a name without spaces wraps instead of widening the button). `Theme.font-size-question: 32px`.

- [ ] **Step 1: Apply the patch**

```bash
git apply --index docs/superpowers/plans/kiosk-i18n/4-layout.patch
```

Layout rules it implements:
- My wallet / Family wallet: a content column (heading, balance, beneficiary buttons, then a stretch spacer) and a fixed 200 px right column holding the navigation button on top and the `?` button at the bottom, so the list never runs under `?`.
- Amount select: the Back button is part of the vertical layout (below a stretch spacer), not absolutely placed.
- Result: OK is inside a centred `HorizontalLayout`.
- Confirm / amount headings use `font-size-question` so a three-line recipient name still leaves room for the buttons.

- [ ] **Step 2: Run the tests**

Run: `cargo test -p kiosk-gui`
Expected: lib 77, navigation 15, translations 5, all passed. The new scenario `buttons_fit_the_screen_in_both_languages_with_the_longest_names` checks, for every screen in `en` and `ru` with a 32-character `WWW…` name: every `KioskButton` is at least 60x60 px, lies inside the 800x480 window, overlaps no other button; and the OK button's centre is within 1 px of x = 400.

- [ ] **Step 3: Prove the centring check is not vacuous**

In `kiosk-gui/ui/result.slint` change the `HorizontalLayout { alignment: center; … }` around the OK button to `alignment: start;`, run `cargo test -p kiosk-gui --test navigation`: it must fail with `OK is not centred`. Restore the file.
